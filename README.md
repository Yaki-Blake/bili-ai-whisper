# Bili 本地字幕补全

给 B站**没有字幕的视频**补中文字幕。转写全程在你自己电脑上完成，音频不上传。

**只在视频没有官方字幕时工作。** 有 UP 主字幕或 B站 AI 字幕的视频，扩展默认不接管，只在播放器下方留一条细提示（可一键切换成 AI 字幕），不叠加、不遮挡、不改页面样式。

---

## 实测状态（2026-10-29，本机 i5-12450H / 15.8GB / 无 GPU 加速）

服务端已跑通，数据是真实跑出来的，不是估算：

| 项 | 实测值 |
|---|---|
| 测试视频 | 177 秒，中文，无官方字幕 |
| 音频下载 | 3.12 MB / 0.9 秒 |
| 首句字幕出现 | **4.8 秒**（边转边出） |
| 全片转写完成 | 72.8 秒 → **2.4 倍实时** |
| 覆盖率 | 末句 176.6s / 177s = **99.8%** |
| 缓存命中 | **4 毫秒** |

浏览器扩展侧已在 **Chrome** 实测：脚本注入、`/video/` 与连播页识别、有官方字幕时让路、一键切换成 AI 字幕，均正常。

> 在部分 Edge 环境里会遭遇「所有站点注入一律返回 `Blocked`」——这是浏览器层面的拦截，与扩展代码无关（用一个 20 行的独立探针扩展在 github / B站 / 邮箱 / 问卷星 四个站点复现过）。遇到就换 Chrome，见下方排障表。

## 工作原理

```
页面主世界  bridge.js   ── 带登录态请求 B站接口、嗅探当前 cid
     │ postMessage
内容脚本    content.js  ── 判断有无官方字幕、渲染叠加层
     │ chrome.runtime
后台        background  ── 只做短请求转发
     │ HTTP
本地服务    server.py   ── 下载音轨 → faster-whisper 转写 → 增量返回
```

四个设计要点：

1. **视频识别不靠 URL。** `/list/` 连播页地址里没有 BV 号。改成 hook `fetch` / `XMLHttpRequest`，从播放请求里嗅探 `aid` 和 `cid`，对 `/video/`、`/list/`、`/bangumi/` 都有效。
2. **字幕接口必须带 Wbi 签名。** 实测：签错时接口**仍然返回 `code: 0`**，只是静默丢数据。所以只走 `wbi/v2`，并对结果做末句时间戳校验。
3. **转写任务化。** MV3 后台 worker 会被回收，长请求会中断。改成「提交任务 + 轮询」，浏览器每秒发一次短请求，同时做到边转边出。
4. **关闭 VAD。** 见下方「踩过的坑」第 3 条，这一条不加会直接导致只出 1 句字幕。

## 安装

### 第一步：安装扩展

> **推荐用 Chrome。** 本机实测遇到过一种 Edge 环境：它全局拒绝扩展向页面注入脚本——连一个 20 行、全新安装、权限完备的探针扩展，在 github / B站 / 邮箱 / 问卷星 四个站点全部返回 `Blocked`，跟扩展代码无关；同一份代码在 Chrome 里一切正常。下文路径同时给出两者，优先走 Chrome。

1. 打开 Chrome，地址栏输入 `chrome://extensions/`（Edge 则是 `edge://extensions/`）
2. 打开右上角「开发人员模式」
3. 点「加载解压缩的扩展」，选择 `extension` 文件夹
4. 建议把扩展图标固定到工具栏
5. **每次替换过 `extension` 里的文件，都要回这个页面点一次「重新加载」图标（↻）**，然后按 F5 刷新 B站 页面。旧脚本不会自己更新，这是最常见的「代码明明改了却没效果」

### 第二步：启动本地服务

双击 `server\run.bat`。首次运行会自动：

- 创建虚拟环境（Python 3.11+ 均可，**3.13 实测可用**）
- 用阿里云镜像装依赖（约 400 MB）
- 启动服务并监听 `127.0.0.1:8765`

首次使用 `small` 模型会自动下载（约 480 MB），走 `hf-mirror.com`，之后复用。

看到下面这段就说明起来了：

```
============================================================
  服务地址   http://127.0.0.1:8765
  运行日志   server.log （本目录，可用记事本打开）
  停止服务   按 Ctrl 键加 C，或直接关闭本窗口
============================================================
```

窗口本身不会再滚动输出，**服务的全部日志写在本目录的 `server.log`**。这是刻意设计的，原因见下方「踩过的坑」第 7 条。

### 第三步：确认扩展有 B站 站点权限

`edge://extensions/` → 扩展的「详细信息」→「站点访问权限」，确保 `https://www.bilibili.com/*` 是**开启**的。

这一项关掉时，扩展的脚本根本不会注入 B站 页面，**页面上什么都不会出现，也不报错**。而 popup 仍能正常显示服务状态，很容易误判成「一切正常」。

## 使用

1. 打开一个**没有字幕**的 B站视频，点播放
2. 右下角出现「字」悬浮球，颜色代表状态：

| 颜色 | 含义 |
|---|---|
| 灰 | 待机，或该视频已有官方字幕（已跳过） |
| 黄 | 正在检查 |
| 蓝 | 转写中 |
| 绿 | 字幕就绪 |
| 红 | 出错 |

3. 约 5 秒后第一句字幕出现，之后随转写进度补齐（转写速度是播放速度的 2.4 倍以上，字幕始终领先）
4. 点悬浮球可以调字号、重新识别、导出 SRT、清缓存、检查服务

**先登录 B站。** 未登录时接口不返回 AI 字幕列表，扩展会把「查不到」当成「没有」，白跑几分钟转写。代码里已做拦截提示。

## 踩过的坑（都已在代码里处理）

这几条是实测撞出来的，环境不同时可能还会遇到，记下来省时间：

**1. `pip` 装不上，报 `from versions: none`**
本机 pip 26.1.2 + 清华镜像会直接返回空版本列表，换阿里云镜像正常。`run.bat` 已默认用阿里云，失败再回退清华。
另外**不要**在脚本里 `pip install --upgrade pip`，升级到 26 反而装不了包。

**2. 模型下载卡在「加载模型…」然后失败**
两个原因叠加：
- `huggingface-hub 2.x` 默认走 Xet 传输（`cas-server.xethub.hf.co`），国内镜像不代理这条通道，直接 401 → 代码里已设 `HF_HUB_DISABLE_XET=1`
- 直连 `huggingface.co` 基本下不动 → 已默认 `HF_ENDPOINT=https://hf-mirror.com`

**3. VAD 把人声当静音（最坑的一个）**
silero VAD 在本机把 176 秒音频里的 168 秒判成非语音，只吐出开头一句。对照实验：

| 配置 | 段数 | 有效语音 |
|---|---|---|
| VAD 开 | 1 段 | 8.99s / 176.4s |
| VAD 关 | 45 段 | 176.4s / 176.4s |

所以默认 `vad: false`，改用「关闭 VAD + 幻觉段过滤」。想试可以改 `config.json` 里的 `vad`。

**4. PyAV 版本冲突**
`av 19` 移除了 `av.open(metadata_errors=...)`，而 `faster-whisper 1.2.x` 还在传它，解码阶段直接 `TypeError`。`requirements.txt` 已锁定 `av<19`。

**5. 模型明明下好了，加载还是失败**
`WhisperModel("small")` 每次都会联网核对 etag，网络抖一下就起不来。已改成先扫本地缓存目录里的 `model.bin`，命中就直接用路径加载，完全离线。
（用 `snapshot_download(local_files_only=True)` 判断不行——它要求 snapshot 完整，缺 `README.md` 也会报错。）

**6. 参数调优实测**
`beam_size` 是主要杠杆，`cpu_threads` 没用：

| 配置 | 转写耗时 | 速度 |
|---|---|---|
| beam=5 | 78.1s | 2.3x |
| beam=1 | 44.8s | 3.9x |
| beam=5 + 8 线程 | 75.5s | 2.3x |

默认 `beam_size: 1`，且这个样本上首句反而更准。

**7. 服务进程活着，但所有请求都超时（端口在 LISTENING，一个请求都不回）**

这是本地服务最严重的一次故障，用 `py-spy dump` 抓到 12 个处理线程全部卡在同一行：

```
write (colorama\ansitowin32.py)
  ... logging -> werkzeug log_request -> http.server send_response
```

根因是 Windows 控制台：开了「快速编辑」后，**只要用鼠标在窗口里选中了文字**，任何写控制台的操作都会无限期阻塞。而 `http.server.send_response()` 是先写访问日志、再发响应头，于是每个请求都卡在写日志这一步，浏览器侧表现就是「本地服务响应超时」，重启扩展也没用。

处理方式：`server.py` 在 `import flask` 之前把 `sys.stdout` / `sys.stderr` 重定向到 `server.log`，服务不再依赖控制台。界面上原本靠 python 打印的「监听 …」改由 `run.bat` 输出。

**8. 批处理里的中文被当成命令执行**

`run.bat` 若存成 UTF-8（无 BOM），`cmd.exe` 会按字节解析，遇到多字节中文时偶发错位，把一行拆成两条命令，报出 `'Ctrl+C' is not recognized` 之类的错。

处理方式：`run.bat` 与根目录启动器改为 **GBK（cp936）+ CRLF**，脚本内 `chcp 936`。改这个文件时注意别用 UTF-8 覆盖。

## 排障

| 现象 | 原因与处理 |
|---|---|
| **页面上什么都没有，连悬浮球都没有** | 先判断是浏览器在拦，还是扩展没装好：在 B站 页面按 F12，Console 里敲 `document.documentElement.dataset.bzSub`。返回版本号 = 脚本在跑，问题在 UI；返回 `undefined` = 脚本没进来 |
| **`chrome.scripting` 报 `Blocked`，所有网站都一样** | 这台 Edge 会全局拒绝扩展注入（实测：一个 10 行、全新安装的探针扩展在 github / B站 / 邮箱 / 问卷星 四个站点全部 `Blocked`）。**换 Chrome**：`chrome://extensions` → 开发者模式 → 加载解压缩的扩展 → 选 `extension` 文件夹。同一份代码在 Chrome 里正常 |
| **视频有官方字幕，但屏幕上什么也看不到** | 这是设计行为：扩展检测到官方字幕就**让路**（不接管）。页面下方会出现一条深色细条「本视频自带官方字幕，扩展已让路」，上面有两个按钮：`打开官方字幕`、`改用 AI 字幕`。v0.3.0 起不再静默退出 |
| **提示「未登录 B站」，但浏览器明明已登录** | 0.3.1 前用 `/x/player/wbi/v2` 的 `isLogin` 当判据，而这个接口在参数/签名有偏差时**照样返回 `code:0`**，只是 data 成了空壳，`isLogin` 跟着变 false——把「接口没给数据」误读成「没登录」。0.3.1 起改用 `/x/web-interface/nav` 复核，并在提示里附上检测明细（nav 返回码 / 有无登录 cookie） |
| 状态一直「点一下播放就开始识别」 | 还没点播放。嗅探要等播放请求发出才能捕获 cid。 |
| 提示「服务未连接」 | `run.bat` 没启动，或 8765 被占用。看服务窗口有没有报错 |
| 提示「本地服务响应超时」 | 先看 `server.log` 有没有新记录。没有 = 进程卡住或已退出；有记录但很旧 = 服务被冻结（见「踩过的坑」第 7 条） |
| 页面上完全没反应、没有悬浮球 | `edge://extensions/` → 详细信息 → 站点访问权限，`https://www.bilibili.com/*` 必须是开启的 |
| popup 里「页面脚本：当前标签页不是 B站」 | 这句话的真实含义是**读不到当前标签页地址**，最常见的原因仍是站点权限没给（见上一行）。v0.2.3 起 popup 会直接自己补注入，无需手动操作 |
| popup 里「目标页：读不到地址」 | 当前标签页不是普通网页（`edge://extensions`、`edge://newtab`、扩展页面等），这类页面按设计不允许注入。**先切到 B站视频页，再点扩展图标** |
| popup 里「注入失败」+ 一行英文报错 | 把那一行发我。v0.2.4 起会分别标出是 `css:` / `bridge:` / `content:` 哪一步、报了什么 |
| 启动窗口一闪而过 | 双击 `启动字幕服务.bat`（根目录），或用 cmd 打开看报错 |
| 只出 1～2 句字幕就结束 | `config.json` 里 `vad` 被改成了 `true`，改回 `false` |
| 转写慢得离谱 | 正常：CPU 上 `small` 约 2.4–4 倍实时。20 分钟视频等 5–8 分钟 |
| 字幕有明显错字 | `small` 模型的已知局限。设置里换 `medium`，代价是慢 2–3 倍 |
| 模型下载失败 | 检查 `hf-mirror.com` 是否可达；`config.json` 的 `hf_endpoint` 可改 |
| `pip install` 失败 | 看上面「踩过的坑」第 1 条，或换 Python 3.12 后删掉 `.venv` 重来 |
| 想验证整条链路 | 服务启动后跑 `server\.venv\Scripts\python.exe server\selftest.py` |

缓存位置：`%LOCALAPPDATA%\bili-sub\cache`（转写结果 + 音频，音频超 800MB 自动淘汰最旧）。

## 已知限制

- 只支持 B站普通投稿、连播列表、番剧页。其他站点不支持。
- 只做中文转写。外文视频需要翻译，本工具不处理。
- 不做术语校正。Whisper 对专业名词有稳定错法（「双非」→「双肥」这类），容忍度高就没影响。
- 未登录的 B站账号拿不到 AI 字幕，会让判断失准。
- 番剧/影视区部分内容有版权保护，`playurl` 可能取不到音频流，会直接报错。
- 转写结果按 `cid` 缓存，同一视频再次观看直接秒开。

## 目录

```
bili-sub/
├── 启动字幕服务.bat      根目录一键启动（转调 server\run.bat）
├── extension/            浏览器扩展（MV3）
│   ├── manifest.json
│   ├── background.js     短请求转发、设置托管
│   ├── content/
│   │   ├── bridge.js     主世界：签名、接口、cid 嗅探
│   │   ├── content.js    隔离世界：编排与渲染
│   │   └── content.css
│   ├── popup/            工具栏弹窗
│   └── options/          设置页
└── server/               本地服务
    ├── server.py         Flask 路由与任务队列
    ├── asr.py            faster-whisper 封装、幻觉过滤
    ├── bili.py           音频下载、Wbi 签名兜底
    ├── config.py         配置读写
    ├── selftest.py       接口级自检脚本
    ├── requirements.txt
    └── run.bat           一键启动（首次会建 .venv、装依赖、下模型）
```

`server/.venv/`、`server/server.log`、`server/config.json`、模型缓存都在 `.gitignore` 里，不进仓库。
